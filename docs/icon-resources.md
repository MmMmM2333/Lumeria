# 图标资源生命周期

布局记录需要哪些图标，显示场景决定何时加载。启动时不用解码所有图片，后台再分批准备可能用到的内容。

## 加载与准备

`retainLayout` 同步保留布局资源；当前场景请求触发前台加载，加载并发为 4。后台清单只含桌面普通应用和文件夹首页最多 9 个缩略图，不遍历所有未打开文件夹内部内容。首次呈现等待当前场景所需资源，后台无关请求不阻塞已就绪的帧。

后台每批限制为约 4 MiB 纹理估算或 4 ms，运行态批间等待 16 ms；前台工作到来时让出。单张解码不可抢占，这些是软预算。窗口暂停时不继续预热。

## 驻留与释放

当前图标 GPU 软预算是 **320 MiB**，按 RGBA 与 mipmap 估算。它不预留显存，也不包含文字、背景、渲染目标和驱动开销。

- 达到预算后停止后台预加载，不边淘汰边扫描完整布局。
- 前台需求允许超预算，之后按最近使用顺序卸载冷纹理；当前场景及隐藏过渡仍引用的纹理受到保护。
- GPU 上传成功后释放 CPU RGBA，保留图片的编码数据供恢复。RGBA 为零不等于图标不占 CPU 内存。
- 原文件后来被覆盖或删除，不改变已经加载的快照；显式换图标走资源替换流程。
- 布局移除资源后，只要还有场景使用它，就延迟销毁；异步加载完成后也要确认资源没有被销毁。

320 MiB 预算用于减少大布局中的反复解码与上传；超过预算时仍按上述规则回收冷纹理。

## 设备恢复

呈现前检查场景资源；GPU 数据丢失后用编码快照重新解码并上传。异步完成时使用当前 renderer，不能继续写入已替换的设备。恢复期间保持上一帧并暂停动画推进；失败时报告错误，避免静默显示缺图。

图标 GPU 状态检查依赖锁定的 Pixi 实现。升级渲染器时应复核设备丢失、同设备卸载、再次访问冷纹理及实际像素恢复。

## 调试入口

`iconResidency` 提供预算、驻留估算、数量和后台队列。队列清空可能是达到预算，不能据此认定全部布局已准备。虚拟应用列表的冷图标完成后只更新对应行，已销毁行不接收更新。
