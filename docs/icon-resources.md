# 图标资源生命周期

布局记录需要哪些图标，显示场景决定何时加载。启动时不用解码所有图片，后台再分批准备可能用到的内容。

## Windows 资源提取与缓存

快捷方式优先使用显式图标路径和索引；普通 EXE 未指定索引时使用资源枚举首组，不假定资源 ID `1` 是应用图标。只在该组内选择尺寸，不跨组用文档或内部功能图标替代应用图标。资源提取失败后保留 Shell 回退及其边缘光晕检测。

组内按 PNG／DIB 头部的实际尺寸择优，支持目录标记为 256、实际为 512 或更大的图像。尺寸相同再比较色深与编码；PNG 同时保留目录中的低色深提示，避免展开为 RGBA 的抖色版本替代全彩图案。损坏或不支持的帧依次跳过；仅有 32／48／64 像素时保留真实分辨率，不补成大透明画布。DIB 解码为 RGBA 后无损缓存 PNG，已有 PNG 经解码校验后保留原字节。

当前手写 DIB 解码支持未压缩的 1／4／8／24／32 位图及常见 Windows 头部；其他压缩格式回退到组内下一帧或 Shell。图像单边限制为 4096 像素，PNG 解码缓冲上限为 64 MiB，防止异常资源分配过量内存。

PNG 快照统一以 `icon-content-<内容摘要>.png` 存储，不同来源的相同 PNG 共用路径和纹理身份。文件来源引用使用 `file-v6`、候选使用 `choice-v3`、Windows 应用使用包身份的 `windows-app-v2`，记录内容文件名和文件修订。快捷方式的解析资源路径／索引及资源大小／修改时间参与来源修订；包版本变化重新提取。内容变化得到新路径，内容相同继续复用，不覆盖用户已选的旧快照。

来源引用命中时只检查内容文件修订，不重新读取／哈希整张 PNG。候选列表使用一份清单，完整提取后原子发布，避免每个候选分别写索引；提取失败不缓存空结果或部分清单。缺失或被改写时重新提取，失败不留下有效缓存。产品扫描由目录通知与周期校准触发；相同大小和时间元数据的内容替换不在检测范围内。自定义上传的 PNG 在写入前解码校验，旧图标缓存保留兼容引用。

旧缓存可能被布局中的自定义图标引用，因此本次不自动删除或覆盖；用户已选图标保持原快照。未来清理缓存时须先核对布局引用。相关提取与缓存回归在 `crates/lumeria-core/src/icons_tests.rs`。

## 加载与准备

`retainLayout` 同步保留布局资源；当前场景请求触发前台加载，加载并发为 4。后台清单只含桌面普通应用和文件夹首页最多 9 个缩略图，不遍历所有未打开文件夹内部内容。首次呈现等待当前场景所需资源，后台无关请求不阻塞已就绪的帧。

后台每批限制为约 4 MiB 纹理估算或 4 ms，运行态批间等待 16 ms；前台工作到来时让出。单张解码不可抢占，这些是软预算。窗口暂停时不继续预热。

选择器的候选提取在数据服务后台线程执行，返回 ID 和路径。虚拟列表仅为可见行和少量邻近行请求纹理；列表和弹窗复用桌面仓库的四路并发、加载去重及设备恢复。临时视图持有独立引用，关闭／滚出时释放，最后一次释放后保留 30 秒方便返回或重开；超出 GPU 预算仍可卸载冷纹理。列表变化用数据身份判断，刷新不序列化 PNG 内容。

## 驻留与释放

当前图标 GPU 软预算是 **320 MiB**，按 RGBA 与 mipmap 估算。它不预留显存，也不包含文字、背景、渲染目标和驱动开销。

- 达到预算后停止后台预加载，不边淘汰边扫描完整布局。
- 前台需求允许超预算，之后按最近使用顺序卸载冷纹理；当前场景及隐藏过渡仍引用的纹理受到保护。
- GPU 上传成功后释放 CPU RGBA，保留图片的编码数据供恢复。RGBA 为零不等于图标不占 CPU 内存。
- 原文件后来被覆盖或删除，不改变已经加载的快照；显式换图标走资源替换流程。
- 布局移除资源后，只要还有场景使用它，就延迟销毁；异步加载完成后也要确认资源没有被销毁。
- 临时视图不会销毁其他场景共享的纹理。资源修复并完成扫描后显式重试失败源，通知仍存活的场景；不会每帧重试无法读取的文件。

320 MiB 预算用于减少大布局中的反复解码与上传；超过预算时仍按上述规则回收冷纹理。

## 设备恢复

呈现前检查场景资源；GPU 数据丢失后用编码快照重新解码并上传。异步完成时使用当前 renderer，不能继续写入已替换的设备。恢复期间保持上一帧并暂停动画推进；失败时报告错误，避免静默显示缺图。

图标 GPU 状态检查依赖锁定的 Pixi 实现。升级渲染器时应复核设备丢失、同设备卸载、再次访问冷纹理及实际像素恢复。

## 调试入口

`iconResidency` 提供预算、驻留估算、数量和后台队列。队列清空可能是达到预算，不能据此认定全部布局已准备。虚拟应用列表的冷图标完成后只更新对应行，已销毁行不接收更新。

实现：[驻留策略](../src/rendering/native/nativeIconResidency.ts)、[恢复资源](../src/rendering/native/nativeRecoverableIconSource.ts)。相关测试包括 `nativeIconResidency.test.ts`、`nativeRecoverableIconSource.test.ts` 和图标加载测试，由 `npm test` 执行。
