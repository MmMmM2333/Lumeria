# 应用导入实验页

运行 `npm run dev:import-lab`，打开 http://127.0.0.1:4186/tests/browser/importLab/index.html 。

此页是中文开发原型，使用独立浏览器存储 `lumeria.import-lab.generic.v1`，不读取真实目录或正式布局。`重置全部实验` 只重置此页。快捷键、窗口模式和登录启动仅用于演示首次引导，不修改系统设置。入口仅在 Vite 开发模式下挂载，不加入 Native 或 Motion Lab 发布构建。

## 建议试验顺序

1. 首次使用中选择来源与导入布局，观察 示例应用组 / 工具合集 分组及 示例播放器 单应用展开。
2. 完成导入，选择 工具合集 文件夹并改名；点击“查看内容”后可以选择成员，移到其他文件夹或启动台末尾。
3. 模拟安装 工具合集 新工具，自动扫描：新增入口只追加到末尾。点击设置旁的“＋ 新增 N”确认加入改名后的文件夹，可以撤销。
4. 移除 示例播放器，再扫描、模拟重启：它不应回来。手动扫描中默认不选中，主动重新添加才恢复。
5. 隐藏启动台后安装附加应用组 并扫描，重新打开才显示新增提示；选择末尾并确认放置后，重复扫描不再提示。
6. 模拟来源离线，观察布局不变；解散文件夹、手动建文件夹和排除应用后重复扫描，检查用户选择被保留。

左侧“来源规则”可分别控制分组及单应用文件夹；后续更改仅用于新增建议。右侧显示操作记录、扫描决策与隐藏记录。扫描时序由按钮显式推进，便于复现；尚未模拟定时任务、安装器文件抖动或 OS 级目录监听。

## 逻辑边界

`src/domain/appImportPlan.ts` 消费已经完成覆盖、语义去重和过滤的 `ScannedCatalogApp`，由 Native 导入流程共用；浏览器没有重新实现 Rust 快捷方式识别。测试样本保留双开始菜单来源和深层相对路径，过滤/合并结果在说明面板展示。

首次生成普通文件夹，仅保存分组来源用于后续建议。自动扫描不整理已有布局；整理建议只针对本批尚未手动移动的新增图标。解散来源文件夹会抑制该分组再建。手动创建同名文件夹不自动关联。撤销仅在没有后续布局操作时有效，防止旧快照覆盖新整理。

来源离线模拟保守地阻止整次扫描应用，不代表正式产品已实现逐来源容错。单应用展开转文件夹、复杂版本迁移等规则仍可以通过本页讨论，尚未接入正式应用。

验证：`npm run test:import-lab`，另运行 `npm run typecheck:app`。

## 手动扫描两步导入

安装样本后不运行自动扫描，直接打开“手动扫描 / 恢复”：
1. 真正新增与已自动添加但待整理的应用默认勾选；已移除、此前暂不添加默认不勾选。支持搜索。
2. 下一步按所选成员重新生成放置预览。与自动新增共用放置预览：每组仅“启动台末尾 / 建议方案”两个单选项，没有可靠建议时只说明末尾结果。建议明确新建或加入现有文件夹；成员和目标不变时返回保留选择。
3. 确认后一次性应用并清除所选应用的待处理提醒。未选中的未添加应用记为暂不添加，后续自动扫描跳过，但不加入永久排除列表；手动扫描仍可选。取消窗口不更改这类记录。
4. 预览依赖的布局或来源改变时，刷新预览并要求再次确认；来源离线不能提交。可撤销，后续布局操作使旧撤销失效。

自动发现的新应用入口现位于搜索栏右侧的设置/扫描按钮旁，显示“＋ 新增 N”，不再使用顶部信息条。设置/扫描按钮在原型中直接打开扫描流程。用户确认手动导入后不会收到同一批新增提醒。

统一预览组件：`PlacementPreview.vue`。手动入口确认添加，自动入口确认放置；末尾方案也完成本批处理。关闭表示稍后处理，保留新增入口。多个同来源候选文件夹无法唯一确定目标时不建议合并。
