# 输入、搜索与窗口

## 输入归属

Native 将指针、滚轮、键盘和文本事件交给共享交互逻辑。设置、弹窗、文本控件和桌面各自有输入作用域；取消时同时释放指针捕获、清除触控 ID 和交互期限，避免界面看似结束但输入仍被旧会话占用。

文件夹关闭动画保留的节点不是普通打开状态。关闭残影、其他桌面图标及空白区必须分别命中，不能用一个“正在关闭则忽略全部按下”条件阻止新操作。

## 搜索与文本

Tab 从搜索输入返回结果导航时保留隐式文本会话：方向键导航，文字、退格和 IME 继续编辑查询。真正转移到其他控件时才释放搜索输入归属。验证必须经过实际鼠标命中和原生文本事件，直接调用 `focus()` 不能覆盖完整链路。

主窗口与 GPU 子窗口之间的焦点变化不一定意味着离开应用。文本会话需要在同一输入路由内接收子窗口字符和 IME，并用实际焦点窗口换算候选框坐标；应用外失焦则正常结束会话。

搜索索引应随目录内容变化更新，不在每次按键重新收集完整布局并计算拼音。搜索视图的节点复用与桌面缓存边界见[场景更新](rendering.md)。

## 触控板

连续输入要区分主动手势、惯性和取消阶段；一次主动手势提交一页后，其尾部惯性不能再次连翻。普通鼠标滚轮和列表滚动保留各自消费方式。

默认显示限速为每秒 4 页；0/6 对照档只用于调试，不写入用户配置。

设备型号、系统事件来源和 DPI 会影响输入表现。合成 wheel 回放能验证状态机，不能代替真实触控板手感。

## 全屏与 DPI

全屏外框使用所在显示器的物理边界；启用超扫时每侧增加 1 物理像素。接到 DPI/display 通知后先校正全屏边界，再同步逻辑尺寸与 backing，不能依赖跨屏重新打开才更新。

全屏窗口不保留 `WS_THICKFRAME` 和 `WS_MAXIMIZEBOX`，避免 Win＋方向键触发贴边或最大化后，系统约束与全屏边界校正冲突。保留最小化支持，退出全屏只恢复模式负责的样式位，显示和隐藏由可见性流程管理；回归需覆盖方向键后通过快捷键与托盘重新唤起。

窗口模式保留自己的还原位置。双屏固定缩放的来回移动，与在同一屏修改 Windows 缩放，是不同测试。测试时分别检查两种情况的窗口边界、文字密度和实际命中。

创建或恢复渲染器时先配置根 GPU 表面，再同步窗口。同步失败保留待处理变化，恢复完成后补发尺寸和 DPI 更新，刷新背景、文字与设置布局。呈现超时从待呈现帧开始计时，闲置时间不计入。

实现入口：[指针路由](../src/native/product/nativeInputRouter.ts)、[键盘路由](../src/native/product/nativeKeyboardRouter.ts)、[可见性控制](../src/native/product/nativeVisibilityController.ts)。

隐藏后唤起时，先在隐藏状态提交带背景且桌面透明度大于零的开场帧，再恢复系统材质并显示窗口。关闭结束帧与入场动画的初始帧均可能透明，不能把任意一次 Present 当作可显示的内容。背景从开场帧就按配置绘制，图标和控件继续入场动画；最小化恢复先还原窗口，再等待运行状态，避免在暂停的渲染器上等待隐藏帧。

保留较大的 GPU 缓冲区可以减少 resize 时重复分配，但会增加资源占用。应用完成帧数不等于显示器扫描帧率；比较方案时还要检查实际画面、命中及跨屏行为。
