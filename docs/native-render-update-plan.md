# Native 场景更新与动画呈现分离方案

状态：运动呈现与结构提交分离已实施。2026-09-12，基于 native 分支当前代码及隔离翻页实验。第 1–9 节保留方案与其他排查方向，第 10 节记录实际交付和验证。

## 1. 目标与证据边界

目标：让结构未变化的动画帧不再重建完整桌面渲染计划、递归复制布局、遍历全部图标资源或刷新无关 UI；保留原版视觉、命中测试、状态提交时序及资源生命周期。

隔离实验使用相同三页、63 个顶层条目的布局，往返翻页 8 次：基线私有工作集 252→395 MiB；仅缓存页面快照 236→360 MiB；跳过不变的场景提交 219→305 MiB；运动回调不提交场景 219→262 MiB。基线 JS 堆容量 58→174 MiB。场景处理累计约 4.5 秒，跳过不变场景提交后约 1.1 秒。

这些实验确认逐帧场景提交是显著贡献者，没有证明所有峰值均由某一函数分配。跨进程初始化、GC 和资源驻留存在波动，不承诺上述差值就是产品收益。实验快捷方式不直接进入产品。原始数据位于 `.codex-dev/page-memory-results/`。

方案阶段的范围为制定方案和排查其他分配路径，用户随后授权实施渲染更新分离。实施不更换 Dawn、不调整 GPU 分配策略、不强制周期性 GC，也不顺带重构设置系统。

## 2. 复用现有架构

当前路径：`NativeDesktopScene.connectAnimationHost → host.commit → nativeMain.renderScene → commitScene → NativeDesktopScene.commit → updateStructure → updateScene(allowPlanReuse:false)`。

复用：

- `renderInvalidation.ts` 的更新标记与合并机制。
- `desktopLayerFrames.ts` 的 structure、interaction、visual、handoff、diagnostics 帧契约和工作量统计。
- `DesktopLayer` 对应的局部更新方法。
- 原版 `desktopPresentationLoop.ts` 的脏状态消费、运动及呈现语义。
- native 已有的 frameScheduler、beforeRender、presented 和恢复生命周期。

只保留一个帧时钟：不把原版 RAF 循环直接叠加到 native frameScheduler 上。优先复用原版更新逻辑；若需抽取共享的纯逻辑，先确认 Web/native 两端调用及测试。

## 3. 三种职责

### A. 状态提交

输入事件或模型变化同步更新权威业务状态，标记所需更新。连续输入始终基于最新状态计算，不等待下一帧；同一帧的重复通知合并。

原 `requestSceneRender()` 各调用点迁移到有明确原因的更新请求，使用集中定义的原因字符串，避免任意字符串被误分类。迁移期间未分类调用保守走 structure；完成时逐个清除无依据的兜底，而非长期让所有事件退化为全量更新。

### B. 按变化提交场景

每个脏通道仅构建自己的帧数据。structure 覆盖同批局部状态时，使用完整、最新输入一次提交，不再重复执行相同更新。没有脏状态时不构建空帧、全量快照或渲染计划。

布局、交互、视觉快照分别只保存最近有效版本；依赖变化时重建。不要保存随帧号增长的历史缓存，不用全量 JSON 序列化来判断是否变化。

### C. 动画呈现

由现有 native 调度器推进 motion、处理必要的文件夹节点交接、更新变换和脏的命中边界、绘制并完成 presented 回调。普通轨道位移不请求 structure。

业务 UI（搜索框、工具条、文件夹名称编辑器、通知、标题栏）按自己的输入变化更新；仅动画中的控件继续更新运动参数。保留 presented 中窗口最大化状态同步、文件夹交接确认及应用关闭帧确认。

## 4. 更新分类

| 触发 | 处理 |
|---|---|
| 初始化、设备/表面恢复后重建 | 完整 structure 和必要资源同步 |
| 布局增删、排序、拖拽投影变化、搜索结果变化 | structure；只重建已变化的布局快照 |
| 页面目标改变、需要显示的页面集合改变 | structure；节点按稳定 key 复用 |
| 纯轨道位移、透明度/缩放插值 | motion；需要同步场景根状态时走 visual |
| 指针焦点、选择、悬停、目标失效徽标 | interaction；核对字段消费者确实刷新对应节点 |
| 编辑模式切换、名称/字体/图标大小或网格设置变化 | 按真实依赖提交；影响结构或测量时明确升级 structure/geometry |
| 窗口尺寸、DPI、显示器切换 | geometry，当前 ledger 会升级 structure；单独合并，不逐事件重复提交 |
| 文件夹节点交接、所有权及关闭阶段变化 | handoff，必要时 interaction/structure；使用现有阶段语义 |
| 图标加载完成 | asset：已有节点更新纹理并请求绘制；只有测量/布局确实变化才升级 |
| 调试覆盖层变化 | diagnostics，不把所有产品状态都误放进此通道 |
| 设置面板/菜单/通知等独立 UI | 仅更新对应组件；其显示若影响桌面交互或视觉，再标记相应通道 |

注意：`makeDesktopLayerFrameUpdates` 中 asset/motion 本身不会生成结构帧，必须显式保留资源回调与绘制请求。已有局部帧的字段存在并不保证所有节点消费者已覆盖；实施时逐项核对，缺项才补最小契约和测试。

## 5. 帧顺序、页面显示范围及一致性

1. 输入同步提交模型状态、标记更新；需要立即查询新布局的调用点，先消费必需更新再查询，保留当前同步语义。
2. 帧开始消费此前的脏状态，为新运动建立正确的目标和节点。
3. 推进运动；依照最新呈现位置计算需要显示的页面集合。
4. 集合或文件夹交接阶段变化时，补一次必要更新；同一集合的连续帧不重建结构。
5. 更新世界变换及必要的命中边界，随后绘制。
6. 呈现成功后再确认交接/关闭完成。没有呈现成功不得提前释放源节点或隐藏窗口。
7. 提交过程中新产生的更新不得丢失：consume 只取走当批请求，后续标记留给下一次消费；禁止同步递归重入。
8. 脏状态、运动、交接及待处理资源均为空时停止调度；隐藏/失焦激活行为按既有规则执行。

页面显示范围沿用当前语义：目标页、相邻预备页以及实际呈现位置跨过的页；只在集合或页的交互角色变化时更新。快速反向、0→2→0 跳转及触控板中途打断，必须保留仍在屏幕上的源页。动画结束可收缩范围并做一次最终交互提交，但不能把“收尾提交”变成持续逐帧提交。

命中测试不能直接依赖上一帧的陈旧 bounds：按现有输入同步入口更新必要变换/边界。待销毁节点仍通过已有帧后清理和所有权机制释放。

## 6. 缓存与资源处理

- 页面快照跟随布局、拖拽投影或回滚投影的真实变化；不能只以 pageIndex 作为缓存键。
- 交互快照只在焦点、选择、拖拽、编辑模式或相应目标状态变化时更新，不能把变化中的 Set/Map 当作永远稳定。
- `collectTextureItems` 和 `retainLayout` 的所有权同步移到布局/图标来源变化边界。可见资源优先级仍随页面显示范围变化更新，不能因为省遍历而漏加载邻页。
- 保留纹理共享、异步取消及 generation 检查；迟到回调不能更新已销毁节点或旧设备。
- 字体/DPI/尺寸变化必须使对应测量缓存失效。设备恢复强制重建必要场景和 GPU 资源。
- 不池化完整业务快照来掩盖高频重建；确需复用临时容器时限定所有权与生命周期，并以分配数据为依据。

## 7. 实施文件与顺序

1. `src/native/nativeMain.ts`：盘点全部直接 renderScene、requestSceneRender、编辑 changed、resize、资源和模型回调，建立分类；拆开业务状态捕获、桌面提交和独立 UI 更新。
2. `src/rendering/native/NativeDesktopScene.ts`：支持按通道提交；动画回调退出无条件完整 commit，补页面显示范围变化和必要边界同步；保留 presented 交接。
3. `src/native/nativeEditing.ts`：若现有 changed() 不携带足够信息，给它最小的更新原因契约，区分指针运动和布局投影变化；不要通过深比较整份布局推断。
4. `renderInvalidation.ts`、`desktopLayerFrames.ts`、`DesktopLayer.ts`：优先直接复用；只有确认局部更新缺失或共享语义不足时修改，并同时覆盖原版测试。
5. `nativeIconResidency.ts`：只有调用边界迁移需要时调整，保留 ownership 与优先级契约。
6. 用现有工作量计数与隔离探针验证，删除正式路径上的临时探针和实验开关，保留可复现实验结果。

实施以可验证阶段推进：先完成分类且维持原行为，再启用普通桌面翻页的运动路径，随后迁移文件夹/拖拽/窗口几何路径，最后移除过渡性全量兜底。阶段间保持功能完整，不把未覆盖路径静默当作完成。

## 8. 验收

行为：鼠标/键盘/触控板翻页、连续反向与跨页跳转；动画中点击图标、右键菜单、搜索和修改布局；文件夹打开/关闭/翻页/改名/拖出/合并/回滚；多选与编辑模式；窗口缩放、DPI/显示器变化、隐藏恢复、失焦首次点击；资源失败及恢复；GPU 设备/表面恢复。

自动检查：没有内容变化且页面显示集合稳定的普通 motion 帧，fullPlanBuilds 和 structureFrames 增量应为 0；纯动画不重建布局快照、不执行全量 retainLayout；事件风暴合并后不丢最新状态；动画期间的新通知、纹理完成、选择变化能及时绘制；idle 无持续动画/结构提交。

性能：同机、同构建配置、同窗口与 DPI、同数据集，交错运行前后各至少 3 次；区分首次翻页和预热后的反复翻页。记录私有工作集/提交量、JS heapSize/heapCapacity/external、场景工作量、帧耗时 P50/P95/P99、纹理/缓冲累计创建与上传量。排除并另记恢复、首次编译等异常样本，不挑选最好一次。检查静置 5/15/30 秒；强制 GC 只作为独立诊断阶段。

验收目标：消除纯运动帧的全量重建；交错测量下临时内存峰值和场景 CPU 成本有稳定改善，帧时间不退化，长期往返后节点/资源存活量不持续增长。不设置未经真实用户布局验证的绝对内存承诺。最终跑相关场景测试、原生 UI smoke 和项目 check；涉及共享更新逻辑时补原版行为验证。

以下仅是代码证据和测量优先级，不代表已经复现同等大小的峰值。

| 优先级 | 已检查入口 | 可能的分配 | 如何验证 |
|---|---|---|---|
| 高 | nativeMain.changeSearch 每次重建搜索 documents，再过滤/分页/复制结果 | 索引对象、字符串、结果数组、节点重建 | 同一目录连续输入/删除查询，分开计索引构建、查询、场景提交；缓存索引须绑定目录/名称变更 |
| 高 | nativeMain.changedApps：capture + JSON.stringify；持久状态变化时 clonePages→commitEditedPages→changeSearch | 大状态序列化、布局副本、搜索与 UI 连带重建 | 千条应用列表，分别搜索、选择、改来源与扫描回调；统计实际持久变化和 UI 通知次数 |

| 中高 | nativeMain 每帧 collectTextureItems→retainLayout | 临时数组及全布局/文件夹扫描；retainLayout 虽有提前返回，调用方遍历已发生 | 对比大量文件夹场景，统计扫描次数及耗时；随布局/来源变化同步 |
| 中高 | 文件夹交接、拖拽投影、回滚与关闭动画仍共用全场景提交路径 | 投影快照、渲染计划、预览节点和边界集合 | 打开关闭/拖入拖出各循环，记录 structure/handoff、节点与资源量；不能直接用普通翻页实验替代验证 |
| 中 | 相邻页节点退出/进入和标签生成 | 成百内部子节点与文字资源；可能有缓存复用 | 单页往返对比不同页面；分别统计构造/销毁、文字重栅格化、池容量；不默认改为无限保留全部页面 |
| 中 | resize/DPI、背景及文字预览 | JS 包装对象，加 CPU 像素数组、Canvas/native 和 GPU 渲染目标 | 分开记录 JS 堆与 external/原生/GPU；不要把整张图片占用都计入 JS 对象堆 |
| 低，先确认启用条件 | motion/debug snapshot、渲染诊断和堆快照 | 全动画对象描述、数组、序列化字符串、探针自身遍历 | 关闭诊断对照；生产未启用的调试函数不能据此认定为产品问题 |

补充：`nativeEditing.projectedPages()` 本身只是从 rollback/drag/layout 三个已有引用中选择，并非每次调用都深拷贝。重点是它后面的 snapshot 和场景更新。`nativeIconResidency.retainLayout` 已对相同布局提前返回，不能误报成每帧重新加载所有图标。现有设置列表含虚拟化，应先查实际重建边界，而不是重复提出“把所有列表改成虚拟列表”。

建议后续实测顺序：完成渲染路径分离后，先测搜索/设置应用列表，再测文件夹与拖拽，最后测 resize/背景预览。每项都把分配速率、GC 后存活量、堆容量和 OS 驻留分开解释；峰值回落不能证明分配合理，容量不立即回落也不自动等于泄漏。

## 10. 实际交付与验证

### 实现

- `nativeMain` 的运动回调只消费待处理状态；没有状态通知时不执行完整 renderScene。
- `NativeDesktopScene` 保存最近的不可变输入，比较布局/交互/诊断/文件夹、网格、viewport 和窗口尺寸等依赖。输入不变时不重建结构；visual 变化走已有局部帧契约；桌面实时滑动只更新 page-track presentation。
- 普通 motion 帧检查实际需要显示的页面集合，只在集合变化时补结构提交；输入同步页码和节点查询的原有语义保留。
- 文件夹进度直接更新面板呈现与名称输入状态；关闭期间单独维护目标几何，跟随桌面恢复变换。所有权改变和 GPU 恢复显式使结构失效；presented 后的交接/关闭确认保留。
- 布局快照、interaction/diagnostic 快照及图标所有权扫描只在相应输入变化时更新。新增快照缓存只保存最近一份，不积累历史。
- 面板呈现参数缓存在文件夹退出和销毁时释放；旧节点沿用帧后释放机制。

实现收敛：native 的 stateHost 通知不带字段原因，因此在场景边界比较稳定输入，而不是再维护一套容易与真实输入脱节的字符串标记。继续使用 native 唯一帧调度器和已有 structure/visual 帧契约。真实布局、焦点、选择及拖拽投影变化仍保留必要的节点同步；现有 interaction 通道仅覆盖部分拖拽/所有权状态，没有把它冒充为通用节点内容更新。消除的是无变化运动帧的全量重建，不是禁止所有结构提交。

### 功能检查

- `npm run check` 通过；后续缓存形状与工作量计数小修通过 native 场景测试、类型检查和 diff 检查。
- 新增测试覆盖不可变快照复用、输入集合/字段变化失效、显示集合稳定时 motion 零结构重建、远端旧页退休。
- 完整隔离 native smoke 通过：桌面/文件夹翻页、快速打断、119 个拖拽视觉样本、10 次重入、搜索/IME/触控板、重命名/右键菜单、20 个文件夹标题 GPU 样本、应用设置、关闭保护、隐藏恢复、resize、资源与设备恢复。
- 已检查实际桌面翻页和文件夹名称编辑截图。多显示器实际 DPI 切换因本机环境缺失跳过；不同 resolution 的原生场景单测已覆盖。
- 关闭目标跟随桌面恢复的回归曾失败，修复为仅更新关闭覆盖层几何后通过。一次早期单独 folder-rename smoke 未生成完成标记，后续完整 smoke 成功覆盖相同文件夹行为，不把早期尝试记为通过。

### 性能结果

相同三页/63 顶层条目数据、同窗口与探针，每轮 8 次翻页，修改前后交错各 3 次；六次均正常退出、无渲染器恢复，运动中间状态和最终目标检查通过。基线源代码从 d7dd669 构建，未重置工作区。

| 指标 | 修改前（三轮） | 修改后（三轮） |
|---|---|---|
| 私有工作集动画峰值 MiB | 371.4 / 394.3 / 385.6 | 269.6 / 277.6 / 276.1 |
| JS 堆容量动画峰值 MiB | 152.0 / 178.5 / 156.6 | 86.0 / 81.4 / 90.6 |
| 状态场景提交次数 | 575 / 578 / 575 | 16 / 16 / 16 |
| 场景处理累计耗时 ms | 4580.5 / 4477.0 / 4669.6 | 162.7 / 180.0 / 164.5 |

另做一组呈现帧间隔与 30 秒静置验证（同探针/同数据，均无恢复）：

| 呈现帧间隔 | 修改前 | 修改后 |
|---|---:|---:|
| P50 | 17.79 ms | 16.86 ms |
| P95 | 48.59 ms | 33.27 ms |
| P99 | 54.57 ms | 35.62 ms |

修改后 30 秒静置时 JS heapSize 约 37.4 MiB、heapCapacity 约 57.3 MiB；私有工作集约 247.5 MiB。此时尚未执行诊断 GC。帧间隔不是 GPU 执行时长，探针有开销；这些数值不等于用户安装版所有布局的绝对内存承诺。没有更改最大帧率，也没有引入自动强制 GC。
