# 私有工作集配对复测

2026-09-11。旧版 f4a3d17，新版 4913cd8。仅隔离诊断，未修改产品实现。

## 方法与完成状态

两版使用同一 Bun1.4.2 / Starter0.3.4 运行包、依赖和 Rust 数据宿主，通过构建插件从 git
读取旧版有差异的源码，注入完全相同的诊断流程。没有切换或覆盖工作区文件。
顺序 old-1 → new-1 → new-2 → old-2，每个新进程使用独立数据目录。
固定900×600、实测resolution=1、无系统材质、190真实图案夹具、36文件夹、3页，非用户布局。
先测入口动画完成后的首场景，再闲置8秒；按1→2→0浏览页面，闲置2秒；打开/关闭默认常规
设置3次，每次打开等待500ms、关闭等待1秒；最后单独诊断GC，再闲置3秒。截图在所有内存
采样后生成，已检查旧版/新版最终视口一致。首场景探针晚于首帧，新版后台已加载到88张。

每阶段记录主Bun进程Windows私有工作集/提交及页类别、JSC heap/external、图标RGBA/编码、
场景节点和文本/资源池。不包含launcher及Rust子进程，不与历史进程树合计混比。
页扫描和诊断自身有扰动；heap先采、Windows页统计随后采，并非原子快照。
每版2轮，范围不是置信区间；GC仅用于机制诊断，不代表用户正常使用阶段。

完成：4个配对样本和2个新版分层样本均正常退出，全部66阶段图标失败数0，布局和分辨率符合
预期。测试PID33460/34004/31256/10016/28052/34444。没有操作用户安装实例或强制其GC。

## 为什么启动收益明显，交互后收敛

旧版首场景heap121.83–128.27MiB（external101.23–107.65），新版约40.4MiB
（external约20.4）。新版先准备实际场景图标，后台逐批上传，避免全量解码临时分配集中堆积。
预热后两版均已加载190张，旧CPU RGBA22.25MiB、新0；heap旧70.5–70.7MiB、新约45.85MiB。
因此收益并非只是新版少加载了一批图标。

旧版浏览全部桌面后大部分图标也已上传，RGBA降到2.27MiB，新版仍为0。两版相同的场景、
文字、动画、设置和原生分配路径开始占更大比重，收益收敛符合资源状态变化。
最终heap旧51.95–52.49MiB，新45.16–47.03MiB；新版扣external后的粗略对象部分约22MiB。
不能以私有工作集减heap得到精确“原生组件账单”，两者覆盖范围及页驻留口径不同。

## 新版分层：空布局、文字占位、图片布局

保持设置、窗口和流程一致。占位组只递归移除customIconPath，保留190项/36文件夹及其A文字
占位；不等于完全不渲染图标，占位也有文字栅格成本。以下两个分层条件各1轮。

| 阶段/指标 | 空布局 | 190文字占位＋36文件夹 | 190图片＋36文件夹 |
|---|---:|---:|---:|
| 预热后私有工作集 MiB | 173.00 | 232.98 | 234.10–235.41 |
| 预热后提交 MiB | 601.41 | 691.22 | 812.03–815.87 |
| 预热后节点数 | 114 | 1911 | 1911 |
| 最终诊断闲置私有工作集 MiB | 207.75 | 259.13 | 268.93–269.10 |

有两点值得后续针对：基础应用即使空布局仍有约173MiB；加完整场景而没有图标图片仍增加
约60MiB。新版图片组与占位组预热私有驻留接近，提交差约121–125MiB；图片成本没有消失，
只是大量CPU解码像素已释放、GPU/驱动资源与私有物理页不一一对应。此结果不意味着图片免费，
也不意味着删1911个节点就能回收60MiB；需继续隔离节点、文字及相关初始化。

## 设置与高水位判断

每次设置打开节点1911→2051，关闭恢复1911；空布局114→254→114。
新版图片组文字活跃纹理约1.22→2.50→1.22MiB，关闭后纹理池约1.46MiB、Canvas池0.53MiB，
3次没有增长。代码closeSettings会destroy并清空shell，shell销毁页面、子节点和动画。
因此没有证据支持“整个设置页面未销毁”或“文字纹理池吃掉百MiB”。

new-1关闭第3次设置heap71.16→诊断GC47.00MiB，但私有驻留282.61→283.23MiB，随后3秒
下降到268.93MiB。new-2的GC也先降heap、未立即降私有工作集。空布局和占位组甚至在这3秒
内私有工作集上升，说明不能把这一步全部变动因果归于GC；运行时/驱动异步工作、分配页保留
和采样扰动都可能参与。本轮未取得函数级原生分配归因，没有证明泄漏，也没有排除长时间泄漏。

## 结论与下一步

当前混合策略对启动及预热私有工作集有可重复收益，交互后效果收敛；190规模残余占用不宜
再首先归因于未上传RGBA。下一项最有依据的是隔离完整场景中预建控件、邻页、文字的成本，
同时保留动画和输入行为；必要时测设置首次初始化路径，但shell本身已按打开时创建，不应
重复提出“让整个设置窗口延迟创建”。空应用固定成本和原生分配器页保留仍需专门归因。
本轮只交付分析，不自动扩大为场景架构重写或资源策略修改。
