# 场景更新与帧顺序

业务状态、场景提交和动画呈现承担不同工作。输入必须立即更新业务状态；把重复渲染工作合并到同一帧，不意味着延迟处理输入。

| 工作 | 负责内容 |
| --- | --- |
| 业务状态 | 布局、搜索、选择、保存和交互意图 |
| 场景提交 | 根据变化更新结构、交互、视觉与资源引用 |
| 动画呈现 | 推进运动、更新几何与命中、绘制、确认实际呈现 |

Native 使用宿主的帧调度，不另外启动一套 RAF。纯位置、透明度或页面运动不应每帧重建整个布局计划。文件夹生命周期、真实成员变化和显示页面集合变化仍可能需要结构更新。

## 合并与缓存

场景控制器缓存上一次生成的场景数据，相关输入没变就复用。结构提交已覆盖同批局部变化时不重复做相同工作；提交前清除待处理位，提交过程中产生的新通知留到下一帧。

桌面保留和搜索使用不同策略：搜索只创建当前页、邻页及翻页途中需要的节点；清空搜索可恢复桌面缓存。编辑、换图标、尺寸或主题变化必须使相关缓存失效，不能用旧缓存掩盖真实变化。

未变化的图标视觉状态可以复用，文件夹缩略图和拖拽残影的显示与释放仍由同一流程管理。动画结束不意味着资源已经可以立即销毁，跨层交接需要确认呈现顺序。

## 窗口与资源

窗口像素边界、逻辑布局与 GPU 渲染缓冲区分别计算。DPI 改变不仅影响 backing，也影响文字密度、命中与全屏边界。资源恢复时重新绑定当前设备和输入对象。

批量工具栏模糊需要背景取样。DComp surface 支持 CopySrc 时使用局部复制；能力未知或不支持时保留整场景中间表面回退，不能把请求的 usage 当作设备实际支持。

## 深度模板纹理尺寸

Pixi 8.20.1 内部深度模板纹理创建后，通过 TextureSource.resize() 规范化为整数物理像素，再交给 GPU 分配。该规则覆盖首次使用遮罩以及 GPU 恢复后的延迟创建，避免小数 DPI 的浮点误差让深度模板比颜色附件多一个像素。

修复由 vendor/electrobun-pixi-native-starter/tools/patch-electrobun.mjs 维护，同时应用于 JS 和 MJS；安装依赖时自动应用，check:pixi-patch 验证完整性。已有及外部传入的深度模板附件沿用原行为。回归命令为 npm run test:pixi-render-target。

## 修改后的验证

结构更新次数、图标重设次数和应用呈现帧间隔分别测量。平均 FPS 不能说明首次操作是否长帧；最终节点正确也不能证明动画期间没有重复图标或交接空白。

实现：[场景控制器](../src/native/product/nativeSceneController.ts)、[场景调度](../src/native/nativeSceneScheduler.ts)、[Native 场景](../src/rendering/native/NativeDesktopScene.ts)。

复用节点时，清空 mask 几何不等于解除绑定。离开使用 mask 的状态时应先解除关系，再隐藏或清空；恢复时重新绑定。相关回归见 [mask 生命周期测试](../tests/browser/pixi-drag-preview-mask-batch.spec.ts)，运行 `npm run test:ui -- tests/browser/pixi-drag-preview-mask-batch.spec.ts`。
