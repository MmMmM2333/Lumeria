# 原生图标加载优化

2026-09-09。基线提交01d30ad，Starter0.3.1。用户授权提交既有成果后推进第一轮加载优化。
范围为读取/解码并发、临时像素复制和测量；全布局加载与保留、原图尺寸、mipmap及设备恢复
策略保持不变。没有实施冷图标预算缓存、首屏优先启动或底层图形架构变更。

## 实现

- IconTextureRepository增加可选maxConcurrentLoads，默认Infinity，Web调用方行为不变。
  原生仓库设置4，槽位覆盖读取文件、Skia解码、Canvas/ImageData转换直到Texture返回。
- 队列与已开始的任务共同纳入pending和来源去重。完成或失败释放槽位；尚未开始且已失去
  引用的来源跳过IO；dispose取消队列，旧代次已开始的结果销毁。保留替换失败的旧图回退、
  帧后回收及显式错误报告。同步异常也能释放槽位，队列排空防重入。
- 原生loader将Uint8Array复制改为同一ImageData ArrayBuffer的视图，保留byteOffset和
  byteLength；像素格式、透明度模式和最终纹理所有权不变，纹理仍持有CPU像素供恢复使用。

## 测量方法

沿用docs/native-icon-stress.md的真实PNG样本：1000条目/48页，200条目/10页；177种不同
图案复制为独立文件和纹理，尺寸不变。900×600、DPI1、RTX3060 Laptop，隔离开发运行包。
图标测试是本地已提取图片的读取和解码，不包含从应用EXE首次抽取图标的时间。

诊断构建只在隔离包注入计时和命令，不给产品添加定时采样。对照包从01d30ad读取仓库和
loader代码；候选包使用工作树。每次独立启动，全部解码后闲置，再逐页呈现直到全部上传，
最后再闲置。主表不强制GC，额外GC及设备恢复位于主内存采样之后。

- 加载时间：启动时iconTextures.synchronize前后performance.now差值，不是整个启动时间。
- 初始峰值：全部加载且首屏闲置后，Windows GetProcessMemoryInfo给出的生命周期peakWS，
  包含到该时刻的整个启动过程，不能解释成纯图片解码峰值。
- 全程峰值：全部页面浏览并闲置后读出的peakWS，不包含后续诊断截图或注入设备丢失。
- 加载期最长采样间隔：10ms定时器在加载区间的实际回调时间，加上区间两端后求最大间隔。
  它是事件循环被阻塞的线索，不是硬件输入延迟或GPU帧耗时。旧版区间仅有一次回调，
  不使用其p95声称具有统计意义。
- 交互就绪计时从诊断模块求值开始，到DevTools注册附近、主要事件处理器已安装时结束。
  不含父进程启动和此前模块导入，不等同于精确的用户首屏可操作时间。

峰值，不能把初始峰值的降幅外推到整个使用过程。闲置有所下降，但没有解除全布局像素保留，
GC/分配器/驱动波动仍存在，不承诺长期总工作集恒定在该范围。

200图标有约9ms加载时间增加，换取更短的事件循环阻塞及更低初始峰值。
这些为有限次数实测范围，不是统计置信区间。与早前没有相同计时探针的压力数据区分使用。

同探针空布局各一次：基线闲置298.64MiB/峰值307.15MiB，候选闲置309.41MiB/峰值309.53MiB。
本轮没有降低原生基础开销；单样本闲置相差约11MiB，无法归因于极少量仓库队列对象或排除
运行时/驱动波动，不把空布局列为改善项。两组均无图标资源、正常退出。

并发数探索：2时1000图标加载443ms、最长间隔13.55ms；8时加载278ms、最长间隔19.27ms。
并发8初始峰值812MiB低于本次并发4，但全程峰值1177MiB更高，存在GC/驱动波动。
选择4兼顾加载时长和执行线程可调度性，不宣称是所有机器的最优值，不添加用户配置项。

加载后12次原生Ctrl+方向键往返：输入注入到下一次presented回调的中位数，基线37.81ms、
候选38.70ms；最大值51.40/47.50ms。每次实际页码均变化正确。未发现明显回归，也不据此
声称翻页帧率提高；这是软件注入到呈现回调，不是硬件按键到屏幕发光的测量。

## 验证与证据

- 共享仓库回归覆盖并发槽位、失败、去重、布局移除、dispose队列取消、旧代次结果、复用、
  同步抛错，并复用已有替换回退、帧后销毁和observer异常测试。
- 原生像素测试验证不同解码的存储独立性、后续图片改写/销毁不影响旧纹理、强制GC后内容保留。
- 200/1000图标均独立source UID计数正确、pending0/failed0，全部页面浏览后GPU数据存在。
  候选1000图标额外执行Bun GC，图标截图正常；注入device-lost后deviceGeneration1→2、
  recoveryCount1，恢复后的实际图标截图已查看。
- npm run check退出0，包含574 typed sources/171 runtime test suites/2 locales/1247 messages，
  保留原有大chunk提示。原生完整smoke退出0，覆盖120帧白框/10次重入、搜索/IME/触摸/拖拽
  取消和保存往返、工具栏GPU采样、触控板路由、文件夹中断与20组标题采样、设置与窗口行为。
- 所有压力样本和smoke实例正常退出，最终实例发现为空。用户已授权将本轮优化另行提交；先前成果已在01d30ad。
