# 触发角

设置 → 常规 → 触发角，点击标题展开选项。开关独立控制启用，关闭时也可预先调整选项。默认关闭，初始选择左上角、停留 80ms、无需修饰键，并在全屏应用中暂停。
四角可多选，停留时间支持立即／80ms／100ms／200ms／500ms，也可自定义 0–10000ms 的整数（0 表示立即触发），可要求按住 Alt、Ctrl 或 Shift。
“再次触发时隐藏”默认关闭；开启后，Lumeria 在前台时再次进入角落会隐藏。
“在屏幕接缝处也触发”默认关闭；开启后每块显示器的选中角落均生效。

## 交互规则

- 停在角落只触发一次，移出稍大的离开区域后才能再次触发。相接热区作为一组，跨到邻屏的相邻角落不会立即反向触发。
- 启用、配置变化、休眠恢复或桌面不可访问后，先离开角落再进入。
- 按着鼠标键进入、缺少所需修饰键或被全屏条件抑制时，本次进入作废；松开鼠标或补按修饰键不会原地补触发。
- 使用显示器完整边界，包含任务栏所在区域；默认排除接缝，开启接缝选项后不排除。
- 窗口隐藏或处于后台时，在触发所在显示器呼出；已处于前台时不因另一屏角落移动窗口。
- 设置、确认框、拖拽、启动／关闭动画及退出阶段不接受触发。检测事件不通过模拟快捷键实现。

## 实现与边界

启动台 `crates/lumeria-hot-corners` 中的独立 Windows 线程通常每 50ms 读取光标位置，停留即将到期时按剩余时间提前采样。热区约 8 DIP，按显示器 DPI 转换为物理坐标；离开范围同样按 DPI 缩放。显示器变更通知立即作废待处理事件，并提示检测线程刷新；每秒完整复查作为后备，变化时清空状态。线程不依赖渲染循环，功能关闭或应用退出时唤醒并 join。
输入桌面不可访问时丢弃停留状态并退避至 500ms，不切换到 UAC 安全桌面。全屏判断检查前台非本进程窗口的覆盖范围，排除桌面、任务栏和普通最大化窗口；不是游戏检测器，也不保证识别所有覆盖层和特殊全屏实现。

几何模块逐屏检查完整热区及其两段边与邻屏投影区间的重叠（任一区间命中等价于先合并接缝区间再求交）。角落只剩不足一个完整热区的外露部分时，默认排除，不生成细小的残余热区。镜像矩形去重；重叠区域根据平台报告的指针所属显示器确定归属，无法确定时不触发。坐标采用半开区间，溢出边界使用饱和运算。

原生端最多保留一条未消费事件，超过 500ms 的事件丢弃；事件带显示器标识与拓扑版本，消费时复核当前完整显示器快照；UI 再用配置代次丢弃过时事件，移动窗口前再次核对目标显示器身份。窗口显示复用现有 visibility controller，最终是否得到键盘焦点仍受 Windows 前台窗口规则约束，不注入按键、不提升权限。

设置字段 `hotCorners` 为可选：旧布局缺少时默认禁用，字段存在时 TS/Rust 两端严格校验。旧的 `hotCorners` 对象缺少 `allowSeams` 时默认关闭，下次保存写入该字段。设置运行态更新参与既有事务回滚，布局快照包含配置；每次配置应用重新开始检测，防止旧事件跨配置生效。

目前只实现 Windows。macOS 应实现独立 AppKit 适配并复用规则；Wayland 需要桌面环境能力。未加入不可运行的平台占位实现。

## 验证

`npm test` 包含原生几何／状态机测试（通过 Cargo 构建 `lumeria-hot-corners`）、TS 配置／事件代次测试、设置事务回滚与布局往返测试。Rust 布局测试覆盖旧配置和非法字段。
真实桌面仍需验证管理员窗口、UAC、锁屏、睡眠恢复、RDP、显示器热插拔及不同游戏的行为；自动化不能替代这些交互验收。

构建归属：触发角 DLL 与应用 Rust workspace 一起维护，由开发／发布构建自动生成并复制到运行目录。Starter 的 `native/frame` 是独立 Cargo crate，仅提供通用窗口桥接与显示器变化通知，使用 `npm run test:native-frame` 验证。窗口定位共用 `prepareWindowActivation`；显示／隐藏策略仍由启动台决定。
