# 启动时全量准备与文件夹分析

2026-09-17。仅实验，不修改产品默认策略。临时脚本通过构建注入到独立artifacts运行时，用户配置不变。

## 场景与口径

- 同机RTX3060 Laptop GPU、1920×1080、128px独立PNG、图标预算320MiB。
- 纯应用：10页×80，800个桌面应用。
- 含文件夹：10页×80桌面项，780普通应用+20文件夹；每文件夹20子项，共1180个叶子应用。文件夹占1个桌面格，但资源数量按子项增加。
- current：产品当前策略；pre：实验放宽含文件夹全桌面保留限制，并在首个可用场景前同步准备桌面标签；all：只放宽全桌面保留，不前置文字；hidden：创建窗口后隐藏，准备好首帧再显示。
- “启动到可用”从nativeMain创建NativeDataHost之前的测量入口到首个可用场景呈现通知，不是OS进程创建至屏幕光学可见。测试主机创建窗口/运行时本身约3.8秒，不可将这里的5秒直接当作所有安装版启动时间。
- hidden不是完整无窗口后台启动，创建后才hide，可能存在短暂窗口显示；仅用于估算隐藏准备再显示的代价。
- 首次跨页：第1→10页立即操作，记录操作至首个presented间隔（不是物理FPS）。文件夹展开耗时包括动画，不等于纯CPU阻塞。
- current/pre的纯应用与含文件夹各2次新进程；all/hidden各1次。顺序样本，操作系统文件缓存未清除，没有做所有交互正确性验收。

## 纯应用800项

|模式|启动到可用场景|文字同步准备|首次远跳首帧|返回首页首帧|
|---|---:|---:|---:|---:|
|当前（全节点已在启动时创建）|4.989–5.039s|0|123.6–127.2ms|28.4–28.6ms|
|首屏前文字准备|5.149–5.285s|254–260ms|61.9–75.3ms|28.9–31.7ms|
|隐藏准备完成再显示（1次）|5.291s|276ms|51.9ms|27.4ms|

纯应用节点构建约245–264ms，本来已经发生在启动时。前置文字准备让首屏晚约0.16–0.25秒、首次远跳缩短约48–65ms；没有消除所有首次呈现开销。工作主要被前移而非消失。隐藏模式准备好以后show/activate至可用呈现约82ms，不是无成本瞬时打开。

图标纹理始终约66.7MiB，文字准备增加的是文字缓存。首屏进程RSS跨样本约525–651MiB、受解码暂存和GC影响很大，不适合用两个RSS读数宣称精确内存增量。CPU记录覆盖准备+往返，不是独立启动CPU切片；因此不以该累计值给出精确启动CPU收益。

|---|---:|---:|---:|---:|
|当前按需挂载|4.426–4.436s|659.3–663.5ms|240.4–246.9ms|252.8–256.4ms|
|仅桌面全挂载（1次）|5.045s|119.9ms|34.5ms|370.0ms|
|桌面全挂载+文字前置|5.232–5.269s|78.5–87.3ms|32.1–32.6ms|369.7–380.9ms|

主要远跳收益来自停止途中挂载：当前远跳重建4–5次、返回6次；实验全挂载远跳重建0。文字前置再减少约30–40ms首帧等待。代价是首屏多等0.61秒/0.80–0.84秒；首屏RSS当前约415–416MiB，all约567MiB，pre约632–654MiB（瞬时而非稳态）。首屏图标驻留当前172张约14.3MiB、实验860张约71.7MiB；后台继续准备子项后会增长。

首次打开文件夹仍创建21个文字纹理（20子项+标题），且实测展开总时长变差。当前文件夹开合会更新桌面交接/源图标可见性，扩大保留集合也可能放大提交成本；具体开合阶段未单独计时，不能仅凭本轮确认为唯一原因。实验只是可行性数据，不能直接取消生产的文件夹保护条件。

## 文件夹为什么要分层

1. 桌面外壳：位置、标题、缩略图。缩略图通常显示3×3；代码还为第一页预览滚动保留至folderPageSize数量，不能简单按9个子图估算所有节点。
2. 图标缓存：全布局会登记所有子项来源，但登记不等于解码、上传或创建全部子项场景节点。
3. 展开内容：首次打开某文件夹才创建内部页面；当前实现会创建该已打开文件夹的全部子页以支持远跳，并非启动时创建所有文件夹的内部页面。

极端例：800个桌面格全部是文件夹、每个20项，则有16000个叶子应用。仅独立128px RGBA+mipmap纹理就约1.30GiB；256px约5.21GiB，尚不含文字/节点/背景。全预热所有内部内容不适合以800个桌面格作为预算依据。

## 建议

- 启动到后台/登录自启：优先利用用户尚未打开的时间，分批准备桌面节点、标题和缩略图；保留预算与中断能力。当前隐藏状态canRun会停止文字预热，需为“启动后台准备”设计独立受控阶段，不能只移一行start调用。
- 用户主动冷启动：不建议无条件等待所有文件夹内容。可以有上限地前置桌面准备，其余继续后台，明确用首屏等待换首次翻页稳定性。
- 含文件夹：先拆开“桌面外壳保留”和“展开内容/动画交接”，修复全外壳保留下首次展开变慢的问题，再允许含文件夹桌面进入保留路径。内部只预热当前/最近使用文件夹或将要打开的首个子页。
- 挂载/预热预算应看桌面节点、缩略图子节点、文字纹理字节与独立图标字节，不能只看页数或文件夹个数。
- 后续验收要覆盖打开/关闭/快速切换、拖入拖出、缩略图滚动、重命名、DPI变化、后台恢复，当前试验不替代这些回归。
