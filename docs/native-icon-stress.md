# 1000真实图标压力测试

2026-09-09。用户授权压力测试；仅创建隔离夹具/诊断包，不改产品实现或用户布局。
当前native工作树035e7c0加已验证的Starter0.3.1/品牌预览优化，未提交状态；沿用应用图标策略。

## 结果

本机两次独立启动：1000图标全部解码、首屏闲置时主应用bun.exe工作集620.51–650.09MiB；
浏览完全部48页并再闲置8秒后735.21–745.25MiB（约0.72GiB）；加载阶段已记录的
进程生命周期峰值1169.79–1175.48MiB（约1.14–1.15GiB）。同包空布局闲置292.90MiB。
浏览后相对空布局增加442.31–452.35MiB，约0.43–0.44GiB。

|空布局闲置|292.90|183.56|607.24|0|
|1000图标，第一轮首屏闲置|650.09|537.53|1153.98|42|

工作集包括该进程的共享/映像驻留页；私有工作集只计私有驻留部分；私有提交是Windows承诺
提供后备的虚拟内存，不能当成同等驻留RAM，也不能与前两项相加。进程详细数值均来自
GetProcessMemoryInfo；内部process.memoryUsage是紧邻但非同一瞬间的旁证，正文不混用。
表中是主应用bun.exe，未计开发启动包装进程、独立数据host或DWM的占用；不是整个进程树总和。
未测实际独占显存，纹理仓库GPU数值只作资源估算。

## 样本与执行方式

- 900×600客户区、DPI1、RTX3060 Laptop；开发诊断包，7列×3行、图标设置128，48页。
  无扫描根目录/全局快捷键，无自定义背景图、无系统窗口材质，保留正常文字和原生渲染路径。
- 只读取本机图标缓存PNG，不复制用户布局。按文件内容去重得到177种真实图案，循环复制为
  1000个不同文件路径及1000个应用条目；图案有重复，缓存纹理不共享，不代表安装了1000个不同应用。
- 保留原图尺寸：863张256×256、93张48×48、6张512×512、17张32×32、11张128×128、
  5张256×268、5张64×64。加载仍走产品loadNativeIconTexture，不做缩图或合成纯色替代。
- 各轮检测到1000个不同texture source UID，pending=0、failed=0，CPU RGBA合计
  235623424字节，即224.708MiB；全部含mipmap的GPU纹理估算约299.61MiB，**非实际进程显存计数**。
- 全布局图片先解码保留；首屏及相邻页有42张上传。依次调用实际commitDesktopPage并等待
  呈现，走完0–47页后确认1000张都具有当前renderer的GPU数据，最终page=47。
- baseline1次，1000图标2次独立进程；各次浏览前/后均取闲置样本。Windows峰值为自进程启动
  累计高水位，第一次加载后读数已经达到上述峰值，浏览后未超过；截图在内存样本之后进行。
- 稳态结果不强制GC。另做诊断GC，第一轮工作集738.72MiB、第二轮712.14MiB，不能将其当成
  用户日常自动达到的占用，也不据此承诺释放全部临时内存。
- 两轮runtime均running，deviceGeneration=1、recoveryCount=0、lastError=null、events=[]。
  第一轮末页实际截图已查看，真实图标正常显示。两轮均正常请求退出，三个目标PID均已退出。

## 含义与限制

约224.7MiB是图标CPU像素副本本身；图标仓库保留它们以支持现有加载与恢复策略。
整体增量还包含文字、场景对象、渲染资源和驱动开销。当前loader的解码Image、Canvas、
ImageData及最终Uint8Array会经过临时分配；结合峰值高于稳态，可以确认加载期容量规划
不能只看加载结束后的数值，但本轮未按分配栈拆出各类临时对象的峰值贡献。

这是48页逐页浏览后的短期容量压力测试，不是1000图标同屏、长期泄漏测试、低内存机器测试，
也不是正式发行包或高DPI的容量保证。若1000张全部为256平方像素，单CPU像素为250MiB；
但不能用这一差额精确外推总工作集，其他尺寸/窗口/图标分布也需要重测。
